## A. 추가 측정 없이 우선 처리할 작업

### A1. raw 보존과 Git 제외

권장 결정은 raw 10개를 로컬에 보존하고 루트 `.gitignore`에
`/bench/2026-09-23_playmode/raw/`를 추가하는 것이다. 아직 적용되지 않았다.
이 인계 문서 작성 요청은 raw 삭제나 커밋을 승인한 것이 아니다.

- 기존 제외 규칙을 보존하고 해당 경로만 제외한다.
- raw 파일명·크기·SHA-256 목록을 작은 manifest로 남긴다.
- Git에는 추출본·메타·소스·패치·manifest를 보관하고, raw가 로컬 별도 보관임을 명시한다.
- 외부 백업은 사용자가 정한 저장 위치와 범위가 있을 때 수행한다.

완료 기준: `git check-ignore`로 raw 10개가 제외되고 CSV·문서가 제외되지 않음을 확인.
이미 추적/스테이징된 raw가 있는지도 확인하고, manifest가 실제 파일과 일치한다.

### A2. 본 측정 표의 자동 재현

현재 `../summarize.py`는 본 측정과 보완을 합쳐 A~D 4회 기준으로 출력한다.
결과 문서의 기본 표는 3회 기준이므로 경고문만으로는 표를 바로 재생성하기 어렵다.

- 런 manifest 또는 명시적 그룹 옵션으로 `main`, `supplemental`, `all`을 구분한다.
- main: S0/T1 × A~D × run1~3 = 24, T1 EDepart/EReenter × run1~10 = 20.
- supplemental: S0/T1 × A~D × run4 = 8, T1 EDepart/EReenter × run11 = 2.
- 파일럿·스모크·무효본을 성능 표에 섞지 않는다. 무효 기록은 별도 목록에 계속 출력한다.
- A~D 누적 시간은 런별 합계를 구한 뒤 런 간 중앙값/최소/최대로 집계한다.
  프레임 풀링 통계와 런별 중앙값의 중앙값을 구별해 각 열의 집계 방식을 적는다.
- E 상위−내부 비용은 각 세션에서 차를 구한 뒤 집계한다. 두 중앙값의 차로 대체하지 않는다.
- 측정 창은 A~D 0~1799, E 0~179만 사용한다. raw 여유 2프레임 제외.
- 구간 GC와 전체 프레임 GC를 분리하고 중첩 마커를 더해 중복 계산하지 않는다.
- 출력에 남은 '아직 채우지 않은 것' 등 M6 이전 안내를 실제 상태로 갱신한다.

완료 기준: 동일 명령으로 §4·§6 표를 재생성하고 모든 값이 반올림 범위에서 일치한다.
main 44 / supplemental 10 / all 54의 유효 런 구성이 검증된다.
차이가 발견되면 유리한 값을 선택하지 말고 집계 정의와 원본 행을 대조해 원인을 기록한다.
보관용 `source/summarize.py`, 변경된 소스 해시와 출력 문서를 함께 갱신하고 변경 이력을 남긴다.

## C. 정확도·반복성을 더 보완할 때만 추가 검증

### C1. 독립 데이터로 프레임 대응 검증

현재 ±5% 또는 절대 5,000 ns 기준은 같은 자료를 보고 정한 탐색적 기준이다.
기존 결과를 사전 기준 검증으로 바꿔 부를 수는 없다.

- 새 실행 전에 허용 기준·측정 창·오프셋 탐색 범위·판정 방법을 문서로 고정한다.
  기존 5,000 ns를 채택할 경우 기존 자료에서 얻은 기준임을 적고 새 데이터에서만 검증한다.
- 새 배치 ID로 T1 A(짧은 구간), T1 D(전환), S0 D, E 두 유형을 포함하는 검증 배치를 설계한다.
  반복 수·실행 순서는 결과를 보기 전에 정한다. 기존 본 측정 표에 자동 합치지 않는다.
- 발화 프레임 일치, 오프셋, 절대/상대 오차 분포, 초과 사례를 함께 보고한다.
- 새 배치 raw는 조사 완료까지 모두 보존하고 재시도마다 고유 ID를 쓴다.

완료 기준: 독립 검증 결과와 모든 예외를 기록한다. 통과하도록 기준을 사후 변경하지 않는다.
기존 `T1_D_run1` frame 31의 원인 미상은 그대로 남긴다. 새 런 통과가 과거 이상치의 원인 규명은 아니다.

### C2. 구간 GC 반복 측정

현재 구간별 GC는 칸당 보완 1런이다. 반복성까지 주장하려면 추가가 필요하다.

- 기존 보완 런과 소스·설정이 동일하고 집계 방식이 호환되는지 먼저 확인한다.
- 비용을 줄이려면 우선 S0/T1 A·D 각 2런을 추가해 기존 1런과 총 3런으로 비교한다.
  전체 A~D·E에 대한 반복성 주장을 하려면 해당 모든 칸도 동일하게 확보해야 한다.
- 차이가 있는 배치는 분리하며, 구간 합계·재구성 호출 수·회당 할당·런 간 범위를 보고한다.
- T1 정지 구간 0 B 관측을 게임 전체 무할당으로 표현하지 않는다.

완료 기준: 주장하는 칸마다 독립 런의 결과와 범위가 있고 할당 중첩 합산이 없다.

### C3. 작은 구간의 오버헤드 분리 — 필요할 때만

현재 프레임 전체 시간의 런 간 변동으로는 마커·하네스 비용을 분리할 수 없다.
이를 분리해야 할 목적이 있을 때 동일 조건의 계측 유무를 번갈아 반복하는 검증과
빈 마커 쌍 등 보조 교정 실험을 별도로 설계한다. 인위적 반복 실험은 보조 실험으로 표시한다.
빈 마커 평균을 실제 결과에서 일괄 차감해 '보정된 실측'으로 만들지 않는다.

완료 기준: 추정 방법·변동·적용 범위를 보고한다. 분리가 계속 불가능하면 한계를 유지하며,
현재 핵심 주장인 재구성 횟수 감소와 구간 누적 비용 비교를 위해 반드시 수행할 항목은 아니다.

## 복구할 수 없는 과거 증거

본 측정 44런 raw와 무효 2런의 raw 추출본은 이미 삭제·덮어쓰기됐다.
기존 백업이 발견되지 않는 한 복구됐다고 주장할 수 없다. CSV를 raw로 변환해 원본으로 대체하지 않는다.
새 측정은 새 증거일 뿐 과거 원본의 복원은 아니다. 이 제한은 결과 문서에 계속 남긴다.

## 추가 실행 시 공통 안전 절차

1. 작업 시작 시 Git 상태·계측 대상 원본을 새로 기록한다. 현재 코드가 기준 커밋과 달라졌으면 그대로 같은 조건이라고 간주하지 않는다.
2. 하네스/계측 복원은 보관 소스와 diff를 검토한 뒤 수행한다. 패치 실패 시 파일 전체를 과거 사본으로 덮어쓰지 않는다.
3. Unity 조작은 Coplay MCP. 연결이 없으면 정적 작업만 진행하고 실행 검증 완료로 표시하지 않는다.
4. 파일럿에서 화면 해상도·카메라·입력 대응·모드 상태·컴파일·콘솔 오류를 확인한다.
   기존 NRE는 Error Pause를 끄는 것으로 해결되지 않는다. 측정 창 안 오류는 원인 확인 후 유효성을 판정한다.
5. 실행 중 Unity 포커스를 유지한다. 스냅샷 복원 전에 현재 사용자 세이브를 보존하고, 과거에 비어 있었다는 이유로 지금도 빈 경로라고 가정하지 않는다.
6. 고유 배치/시도 ID로 모든 유효·무효 기록을 보존한다. 기존 산출물에 덮어쓰지 않는다.
