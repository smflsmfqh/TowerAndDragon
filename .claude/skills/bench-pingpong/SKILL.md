# Bench ↔ Codex 핑퐁 (검토 + 공동 결정 + 자율 진행)

측정·문서 작성은 Claude가, 검토와 공동 결정은 Codex(`codex exec`, 읽기 전용)가 한다.
둘 사이의 주고받기는 전부 파일로 남기고, Claude가 루프를 돈다.
**사용자는 결과만 받는다.** 중간에 사용자에게 묻는 것은 아래 「사용자에게 넘기는 경우」뿐이다.

## 사용자 위임 (2026-10-01)

사용자는 작업 중 생기는 `[결정 필요]` 항목을 **Claude와 Codex가 합의해 정하고 그대로 진행**하도록 위임했다.
이 스킬이 돌고 있는 동안, 마일스톤 문서의 "`[결정 필요]` 항목은 사용자 결정 없이 진행하지 않는다",
"편집은 계획을 보고하고 승인받은 뒤 한다" 같은 규칙은 **"Claude·Codex 합의 + 기록"으로 대체**된다.
나머지 규칙(역사적 기록 보존, 원자료 보존, 수치 예상 금지, 커밋 금지 등)은 그대로 지킨다.

## 구성

| 파일 | 역할 |
|---|---|
| `codex_review.sh` | 한 라운드 실행. 1라운드는 새 세션, 이후는 같은 세션 `resume` |
| `review_prompt.md` | Codex 지침 (검토 기준·심각도·공동 결정 기준). 1라운드에만 앞에 붙는다 |
| `verdict.schema.json` | Codex 응답 형식 강제 (`--output-schema`): verdict · findings · decisions |

## 전체 루프

```
마일스톤 하나 고르기 (진행 문서의 다음 미완료 항목)
 └→ 작업 전 [결정 필요]가 있으면 → 결정 라운드 (§A) → 합의안 기록
 └→ 작업 수행 (측정은 Coplay MCP, 문서·스크립트 편집)
 └→ 검토 라운드 (§B) → 지적 반영 → PASS까지
 └→ 작업 중 새 [결정 필요]가 생기면 → 같은 검토 폴더의 다음 라운드에 「결정 요청」으로 올림
 └→ 마일스톤 완료 처리(진행 현황·작업 로그 갱신) → 다음 마일스톤
멈춤: 모든 마일스톤 완료 또는 「사용자에게 넘기는 경우」
```

마일스톤마다 검토 폴더를 따로 만든다: 작업 폴더 아래 `review/<YYYY-MM-DD>_<마일스톤>/`
(예: `bench/2026-09-23_playmode/review/2026-10-01_N4/`). 기존 폴더를 덮어쓰지 않는다.
결정 라운드와 검토 라운드는 한 요청서에 같이 담아도 된다(라운드 수 절약).

## 요청서 — `round-N-request.md`

Codex는 이 대화를 모른다. 요청서만 보고 판단할 수 있게 쓴다. 해당 없는 절은 뺀다.

```markdown
## 검토 범위
- 대상 파일: (경로. 새로 쓴/고친 곳은 절·줄 범위까지)
- 범위 밖:

## 이번 작업에서 한 일
- 실행한 측정/명령, 런 id, 산출물 위치
- 문서에서 새로 주장하는 수치와 그 원자료 위치

## 직전 지적에 대한 대응        ← 2라운드부터
- R1-1: 고침 — 무엇을 어디서 (파일:줄)
- R1-2: 반론 — 근거

## 결정 요청
### 결정 6 — (제목)
- 배경: (문서 위치 파일:줄, 관련 원자료)
- 선택지: (가) … (나) … (다) …
- Claude 추천과 근거: …
- 되돌리기 비용: …

## 직전 결정에 대한 대응        ← Codex와 의견이 갈렸을 때
- 결정 6: Codex안 수용 / 반론 — 근거
```

## §A 결정 처리

`decisions[]`를 읽고 항목마다:

| 상황 | 처리 |
|---|---|
| `agrees_with_claude: true`, escalate 아님 | **합의.** `conditions`까지 포함해 그대로 실행 |
| Codex가 다른 안을 고름 | Codex 근거를 원자료로 확인. 납득되면 Codex안 채택(합의). 아니면 다음 라운드 「직전 결정에 대한 대응」에 반론 |
| 반론 후에도 불일치 (같은 결정에서 2라운드 연속) | 그 결정만 사용자에게 넘긴다. **그 결정에 의존하지 않는 작업은 계속 진행** |
| `escalate_to_user: true` (또는 Claude가 아래 목록에 해당한다고 판단) | 사용자에게 넘긴다. 의존하지 않는 작업은 계속 |

합의한 결정은 진행 문서의 `[결정 필요]` 모음에 해결로 기록한다:

> **해결 (2026-10-01, Claude·Codex 합의)** — (가) 채택. 근거 요약. 조건: … 기록: `review/2026-10-01_N4/round-1-review.json`

사용자가 나중에 뒤집을 수 있도록 근거와 기록 경로를 반드시 남긴다.

## §B 검토 처리

```bash
bash .claude/skills/bench-pingpong/codex_review.sh <review_dir>
```

- 추론 강도 high라 수 분 이상 걸린다. **Bash `run_in_background: true`로 실행**하고 완료 알림을 기다린다.
- 마지막 줄 요약: `verdict=… new=… unresolved=… decisions=… disagree=… escalate=…`. 전체는 `round-N-review.json`.
- 비정상 종료 시 `round-N-codex.log`를 읽는다. 같은 라운드를 재시도하려면 실패한 `round-N-review.json`/`events.jsonl`을 지우고 다시 실행한다.
- 지적마다 원자료로 직접 확인한다. Codex도 틀릴 수 있다. 맞으면 고치고, 틀리면 근거를 붙여 반론한다.
- `minor`는 반영하되 라운드를 더 돌릴 이유는 아니다.
- 한 검토 폴더의 최대 라운드는 3(`BENCH_REVIEW_MAX_ROUNDS`). 넘으면 스크립트가 exit 3으로 막는다 → 남은 지적을 사용자에게 넘기고, 의존하지 않는 다음 마일스톤으로 간다.

## 사용자에게 넘기는 경우 (이것만)

- 커밋·푸시 (항상 사용자가 직접)
- 원자료(`raw/` 등)·역사적 기록·보관 해시의 삭제·이동·덮어쓰기
- 측정 원칙(`review_prompt.md`의 검토 기준) 자체를 바꾸는 결정
- 포트폴리오에 실을 결론의 방향이 바뀌는 결정 (예: 개선 효과가 없다/반대다)
- 사용자가 이전에 직접 내린 결정을 뒤집는 결정
- Codex가 `escalate_to_user: true`로 표시한 결정
- Claude·Codex가 같은 결정에서 2라운드 연속 불일치
- 검토 폴더 최대 라운드 초과 후에도 남은 blocker/major

넘길 것이 생겨도 **멈추지 말고** 그 항목에 의존하지 않는 작업을 계속한다. 의존하지 않는 작업이 하나도 남지 않으면 그때 멈춘다.

## 최종 보고

1. 진행한 마일스톤과 완료 여부
2. **Claude·Codex가 합의해 정한 결정 목록** (결정 · 채택안 · 근거 한 줄 · 기록 경로) — 사용자가 뒤집을 수 있게 맨 앞쪽에
3. 라운드별 판정 표 (검토 폴더 · 라운드 · verdict · 새 지적 · 해결/미해결/철회 · 결정 합의/불일치)
4. 사용자에게 넘긴 항목과 양쪽 입장
5. 사용자가 직접 확인할 항목 (번호 매긴 명령·기대 결과)
6. 커밋 대상 후보 (검토 폴더 포함) — 커밋은 하지 않는다

## 주의

- Codex는 `read-only` 샌드박스로 돈다(2라운드 `resume`도 `-c sandbox_mode`로 고정). Codex가 파일을 고쳤다고 주장하면 의심한다.
- "Codex PASS"·"합의"는 사용자 검토를 대신하지 않는다. 보고에 그렇게 쓴다.
- 검토 기준(`review_prompt.md`)을 바꿀 때는 사용자와 상의한다.
