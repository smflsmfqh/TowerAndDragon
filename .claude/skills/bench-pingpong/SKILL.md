# Bench ↔ Codex 검토 핑퐁

측정·문서 작성은 Claude가, 검토는 Codex(`codex exec`, 읽기 전용)가 한다.
둘 사이의 주고받기는 전부 파일로 남기고, Claude가 루프를 돈다.

## 구성

| 파일 | 역할 |
|---|---|
| `codex_review.sh` | 한 라운드 실행. 1라운드는 새 세션, 이후는 같은 세션 `resume` |
| `review_prompt.md` | 검토자 지침 (기준·심각도·판정 규칙). 1라운드에만 앞에 붙는다 |
| `verdict.schema.json` | Codex 응답 형식 강제 (`--output-schema`) |

## 절차

### 0. 준비

- 검토 대상과 범위를 정한다. 사용자가 지정하지 않았으면 "무엇을 검토받을지" 한 줄로 확인한다.
- 검토 기록 폴더를 만든다: 대상 작업 폴더 아래 `review/<YYYY-MM-DD>_<짧은-이름>/`
  (예: `bench/2026-09-23_playmode/review/2026-10-01_N5/`). 기존 폴더를 재사용하거나 덮어쓰지 않는다.
- 측정이 필요한 작업이면 측정을 먼저 끝낸다(Unity 조작은 Coplay MCP). 검토는 결과가 파일로 남은 뒤에 받는다.

### 1. 요청서 쓰기 — `round-N-request.md`

Codex는 이 대화를 모른다. 요청서만 보고 검토할 수 있게 쓴다.

```markdown
## 검토 범위
- 대상 파일: (경로 목록. 새로 쓴/고친 곳은 절·줄 범위까지)
- 범위 밖: (이번에 보지 않아도 되는 것)

## 이번 작업에서 한 일
- 실행한 측정/명령, 런 id, 산출물 위치
- 문서에서 새로 주장하는 수치와 그 원자료 위치

## 직전 지적에 대한 대응   ← 2라운드부터
- R1-1: 고침 — 무엇을 어디서 어떻게 (파일:줄)
- R1-2: 반론 — 고치지 않은 이유와 근거
```

반론은 근거(원자료 값, 명령 출력)가 있을 때만 한다. 동의하면 고친다.

### 2. 검토 실행

```bash
bash .claude/skills/bench-pingpong/codex_review.sh <review_dir>
```

- 추론 강도 high라 수 분 이상 걸릴 수 있다. **Bash `run_in_background: true`로 실행**하고 완료 알림을 기다린다.
- 마지막 줄에 `verdict=… new=… unresolved=…` 요약이 찍힌다. 판정 전체는 `round-N-review.json`.
- 비정상 종료 시 `round-N-codex.log`를 읽고 원인을 사용자에게 보고한다. 같은 라운드를 재시도하려면
  실패한 `round-N-review.json`/`events.jsonl`이 있으면 지우고 다시 실행한다(요청서는 유지).

### 3. 판정 처리

- 지적마다 직접 확인한다. Codex의 지적도 틀릴 수 있다 — 원자료를 열어 보고 판단한다.
- 맞는 지적은 반영한다. 문서·스크립트 편집은 이 스킬을 호출한 시점의 사용자 승인 범위 안에서만 한다.
  범위를 벗어나는 수정(재측정, 씬 저장, 측정 설계 변경)이 필요하면 멈추고 사용자에게 묻는다.
- `minor`는 반영하되 루프를 더 돌릴 이유는 아니다.

### 4. 종료 조건

다음 중 하나면 루프를 멈추고 보고한다.

- `verdict=PASS`
- 최대 라운드(기본 3, `BENCH_REVIEW_MAX_ROUNDS`) 도달 — 스크립트가 exit 3으로 막는다
- 같은 지적이 두 라운드 연속 `unresolved`로 남음 (Claude와 Codex 의견이 엇갈림 → 사용자 판단)
- 사용자 결정이 필요한 지적 (`[결정 필요]` 항목, 측정 재설계 등)

PASS라고 해서 사용자 검토를 대신하지 않는다. 보고에 "Codex PASS"라고 쓰되 사용자가 최종 판단한다.

### 5. 보고

응답에 다음을 담는다.

1. 라운드별 판정 표 (라운드 · verdict · 새 지적 수 · 해결/미해결/철회)
2. 반영한 수정 목록 (파일:줄)
3. 반론했거나 남은 지적과 그 이유 — 사용자 판단이 필요한 것부터
4. 검토 기록 폴더 경로

## 주의

- Codex는 `read-only` 샌드박스로 돈다(2라운드 `resume`도 `-c sandbox_mode` 로 고정). Codex가 파일을 고쳤다고 주장하면 의심한다.
- 커밋하지 않는다. 검토 기록 폴더도 사용자가 커밋 여부를 정한다.
- 검토 지침(`review_prompt.md`)의 기준은 사용자의 측정 문서 원칙(미측정 수치 단정 금지, 런 선별 금지, 이식 충실도, 재현 자료 보존, 주장 범위)이다. 바꿀 때는 사용자와 상의한다.
